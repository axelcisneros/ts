TypeScript de principio a fin

Guía de clase, ejemplos y proyecto de migración

De JavaScript a TypeScript con programación orientada a objetos y separación de responsabilidades.

Objetivos de aprendizaje

  • Comprender cómo TypeScript comprueba programas JavaScript antes de ejecutarlos.
  • Modelar datos con tipos, interfaces, uniones y genéricos.
  • Aplicar clases, composición y contratos sin confundir tipos con validación en ejecución.
  • Migrar un proyecto real pequeño y verificar que conserva su comportamiento.

1. ¿Qué es TypeScript?

TypeScript (TS) es JavaScript con un sistema de tipos estático. El compilador tsc analiza el código y emite JavaScript; Node.js o el navegador ejecutan el JavaScript resultante. Los tipos se eliminan durante la compilación.

const nombre: string = "Ana";
console.log(`Hola, ${nombre}`);

El editor puede detectar incompatibilidades antes de ejecutar, ofrecer autocompletado y facilitar refactorizaciones. TS no garantiza que un dato recibido por red sea válido y tampoco sustituye las pruebas.

let edad: number = 25;
// edad = "veinticinco"; // ERROR: string no es number

Inferencia: si escribimos let edad = 25, TS normalmente infiere number. No es necesario anotar cada variable; sí conviene explicitar contratos públicos y datos cuya forma no sea evidente.

Del código a la ejecución

archivo.ts  →  tsc comprueba y compila  →  archivo.js  →  Node.js

noEmitOnError impide producir archivos de salida si hay errores. Una compilación correcta no demuestra que la lógica sea correcta: también hay que ejecutar pruebas.

2. Preparación y primer programa

En una carpeta nueva, inicializa el proyecto e instala TypeScript localmente:

npm init -y
npm install --save-dev typescript
npx tsc --init

En PowerShell de Windows, si la política bloquea los scripts, usa npm.cmd y npx.cmd. Para un ejemplo aislado crea hola.ts:

function saludar(nombre: string): string {
  return `Hola, ${nombre}`;
}
console.log(saludar("Ada"));
npx tsc hola.ts --target ES2020
node hola.js

Resultado: Hola, Ada. Para un proyecto real utiliza npx tsc -p tsconfig.json en lugar de pasar archivos individuales: así se usa la configuración del proyecto.

Opciones esenciales

OpciónFinalidad
strictActiva comprobaciones estrictas, incluidos null y los tipos implícitos.
targetDefine la versión de JavaScript generada.
rootDir / outDirSepara archivos fuente de archivos compilados.
module / moduleResolutionAdaptan módulos y resolución al entorno de ejecución.
noEmitOnErrorNo genera nueva salida si el compilador detecta errores.

3. Tipos básicos y colecciones

const nombre: string = "Lucía";
const edad: number = 30;
const activa: boolean = true;
const sinValor: null = null;
const pendiente: undefined = undefined;

const etiquetas: string[] = ["ts", "poo"];
const precios: Array<number> = [10, 20];
const coordenada: [number, number] = [19.43, -99.13];

Una tupla expresa posiciones con tipos conocidos. Un arreglo normal permite una cantidad variable de elementos. Las versiones readonly string[] y readonly [number, number] impiden cambios mediante esa referencia durante la comprobación de tipos.

Literales y uniones

type Estado = "pendiente" | "completada";
let estado: Estado = "pendiente";
estado = "completada";
// estado = "cancelada"; // ERROR: valor fuera de la unión

Un alias type da nombre a un tipo; no crea una clase ni un valor en tiempo de ejecución. Las uniones también combinan tipos distintos: string | number.

Tipos especiales

  • unknown: valor desconocido; debe comprobarse antes de usarlo.
  • any: desactiva muchas comprobaciones; evítalo si se puede modelar el dato.
  • void: una función no proporciona un resultado útil.
  • never: una función no retorna normalmente, por ejemplo si siempre lanza una excepción.
function fallar(mensaje: string): never {
  throw new Error(mensaje);
}

4. Objetos, interfaces y funciones

interface Persona {
  readonly id: number;
  nombre: string;
  correo?: string;
}

function describir(persona: Persona): string {
  return `${persona.nombre} (${persona.correo ?? "sin correo"})`;
}
const persona: Persona = { id: 1, nombre: "Ana" };
console.log(describir(persona));

? marca una propiedad opcional; al leerla puede ser undefined. readonly limita la escritura desde TS, pero no congela el objeto en ejecución. ?? usa el valor alternativo únicamente para null o undefined.

TS usa tipado estructural: un objeto compatible debe proporcionar las propiedades requeridas con tipos compatibles. Una interface es adecuada para contratos de objetos; un type también permite uniones, tuplas y otras composiciones.

function sumar(a: number, b = 0): number {
  return a + b;
}
function registrar(mensaje: string): void {
  console.log(mensaje);
}
const duplicar = (n: number): number => n * 2;

Un parámetro con valor por defecto puede omitirse. Los tipos de parámetros y retorno permiten detectar llamadas incompatibles; por ejemplo, sumar("2", 3) es un error de compilación.

Intersección

type Identificable = { id: number };
type ConNombre = { nombre: string };
type Usuario = Identificable & ConNombre;
const usuario: Usuario = { id: 1, nombre: "Ana" };

5. Uniones, narrowing y seguridad

Antes de usar una operación específica de un miembro de una unión, demuestra cuál es mediante una comprobación. Esto se conoce como narrowing.

function mostrarId(id: string | number): string {
  if (typeof id === "string") {
    return id.toUpperCase();
  }
  return id.toFixed(0);
}

Datos externos y unknown

function leerNombre(valor: unknown): string {
  if (typeof valor !== "object" || valor === null ||
      !("nombre" in valor) ||
      typeof valor.nombre !== "string") {
    throw new Error("Nombre inválido");
  }
  return valor.nombre;
}
const dato: unknown = JSON.parse('{"nombre":"Ana"}');
console.log(leerNombre(dato));

JSON.parse no valida la forma de los datos. Asignar su resultado a unknown obliga a comprobarlo. Una aserción como dato as Persona no realiza validación; úsala solo cuando exista una garantía real.

Unión discriminada

type Resultado =
  | { ok: true; valor: number }
  | { ok: false; error: string };

function imprimir(r: Resultado): void {
  if (r.ok) console.log(r.valor);
  else console.error(r.error);
}

El campo literal ok permite distinguir las variantes. Con strictNullChecks, una búsqueda puede devolver Tarea | undefined y debe comprobarse antes de acceder a sus propiedades.

6. POO: clases y responsabilidades

interface Completables {
  completar(): void;
}

class Tarea implements Completables {
  readonly id: number;
  titulo: string;
  private completada = false;

  constructor(id: number, titulo: string) {
    if (!titulo.trim()) throw new Error("Título obligatorio");
    this.id = id;
    this.titulo = titulo.trim();
  }
  completar(): void { this.completada = true; }
  estaCompletada(): boolean { return this.completada; }
}

La clase construye objetos y agrupa estado con comportamiento. implements comprueba que la clase cumple un contrato; no copia su implementación. private de TS restringe el acceso durante la comprobación; si se necesita privacidad real en ejecución, considera los campos JavaScript #privados.

Composición antes que acoplamiento

interface Repositorio {
  guardar(tarea: Tarea): void;
  buscarPorId(id: number): Tarea | undefined;
}

class Servicio {
  constructor(private repositorio: Repositorio) {}
  completar(id: number): void {
    const tarea = this.repositorio.buscarPorId(id);
    if (!tarea) throw new Error("Tarea inexistente");
    tarea.completar();
    this.repositorio.guardar(tarea);
  }
}

El servicio depende de un contrato, no de una implementación concreta. El parámetro private repositorio declara e inicializa una propiedad de la clase. El ejemplo es conceptual; el proyecto de práctica usa nombres y operaciones adicionales.

7. Genéricos y utilidades

Un genérico conserva la relación entre los tipos de entrada y salida sin duplicar la función para cada tipo.

function primero<T>(elementos: readonly T[]): T | undefined {
  return elementos[0];
}
const numero = primero([10, 20]); // number | undefined
const texto = primero(["a", "b"]); // string | undefined

También se pueden establecer restricciones:

function obtenerId<T extends { id: number }>(valor: T): number {
  return valor.id;
}
obtenerId({ id: 4, nombre: "Ana" });

Utilidades de tipos habituales

interface Perfil {
  nombre: string;
  correo: string;
}
type CambiosPerfil = Partial<Perfil>;
type NombrePerfil = Pick<Perfil, "nombre">;
type Perfiles = Record<string, Perfil>;
  • Partial<T>: hace opcionales las propiedades de primer nivel.
  • Pick<T, K>: selecciona propiedades.
  • Record<K, V>: describe valores asociados a claves.

Estas utilidades describen tipos; no transforman ni validan objetos en ejecución. Evita genéricos cuando no expresen una relación útil entre tipos.

8. Promesas, errores y límites

async function cargarNombre(): Promise<string> {
  const respuesta = await fetch("https://example.com/api/persona");
  if (!respuesta.ok) {
    throw new Error(`HTTP ${respuesta.status}`);
  }
  const dato: unknown = await respuesta.json();
  return leerNombre(dato); // función definida en la sección 5
}

Esta URL es ilustrativa, no es un servicio preparado para el ejercicio. Una función async devuelve una promesa; comprueba el estado HTTP y valida el cuerpo antes de usarlo.

try {
  const nombre = await cargarNombre();
  console.log(nombre);
} catch (error: unknown) {
  if (error instanceof Error) console.error(error.message);
  else console.error("Error desconocido", error);
}

Este bloque con await superior debe estar en un módulo que lo admita. El ejemplo requiere un entorno con fetch, por ejemplo Node.js 18 o posterior. No ignores los errores ni devuelvas un resultado que aparente éxito.

Lista mental para datos externos

  1. Recibir como unknown.
  2. Validar forma, propiedades y reglas de negocio.
  3. Informar el error si no cumple el contrato.
  4. Operar con el valor una vez comprobado.

La validación de negocio puede seguir siendo necesaria incluso con parámetros tipados: una cadena puede estar vacía y un número puede ser negativo.

9. Proyecto: gestor de tareas en JavaScript

El proyecto adjunto proyecto-tareas-js es una aplicación de consola sin dependencias. Usa datos en memoria: se pierden al finalizar el proceso. No necesita servidor ni base de datos.

proyecto-tareas-js/
  src/
    Tarea.js
    RepositorioTareas.js
    ServicioTareas.js
    PresentadorTareas.js
    index.js
  test/tareas.test.js
  package.json
  README.md
ClaseResponsabilidad
TareaDatos de la tarea, validación y cambio de estado.
RepositorioTareasGeneración de identificadores y almacenamiento en un Map.
ServicioTareasCreación, búsqueda y finalización de tareas.
PresentadorTareasRepresentación de la lista en consola.

index.js crea y conecta los objetos. El repositorio conserva referencias a las instancias; no ofrece aislamiento ni persistencia. El servicio verifica que exista una tarea antes de completarla.

cd proyecto-tareas-js
npm.cmd start
npm.cmd test

En macOS/Linux utiliza npm en lugar de npm.cmd. La salida demuestra una tarea pendiente y otra completada; las pruebas cubren creación, actualización y errores.

10. Migración guiada: configuración

Realiza la migración sobre una copia del proyecto si deseas conservar el original. En la carpeta del proyecto instala TS y crea tsconfig.json:

npm.cmd install --save-dev typescript
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "rootDir": "src",
    "outDir": "dist",
    "strict": true,
    "noEmitOnError": true
  },
  "include": ["src/**/*.ts"]
}

En este contexto NodeNext adapta los módulos a Node. El package.json ya incluye "type": "module". En archivos fuente .ts, conserva los imports relativos con extensión .js: TS resuelve el archivo fuente y Node encontrará el JavaScript compilado.

Agrega al objeto scripts del package.json:

"build": "tsc -p tsconfig.json",
"start:ts": "node dist/index.js"

Sepáralos con comas de los scripts existentes. Renombra todos los archivos de src de .js a .ts; conserva los nombres de los imports con .js. Compila al terminar cada bloque, sabiendo que aparecerán errores mientras falten anotaciones:

npm.cmd run build
npm.cmd run start:ts

Importante: noEmitOnError no elimina una salida antigua de dist. No ejecutes una compilación anterior después de un fallo; corrige los errores y vuelve a compilar.

11. Migración guiada: implementación

  1. Tarea: declara las propiedades id: number, titulo: string y completada: boolean. Anota el constructor y completar(): void. Conserva las validaciones actuales.
  2. Repositorio: importa Tarea y tipa el mapa como Map<number, Tarea>. Anota generarId(): number, guardar(tarea: Tarea): void, buscarPorId(id: number): Tarea | undefined y listar(): Tarea[].
  3. Contrato: crea una interfaz que declare esos cuatro métodos y haz que RepositorioTareas la implemente. El servicio debe recibir el contrato, no la clase concreta.
  4. Servicio: tipa su propiedad de repositorio, el constructor y los métodos. crear(titulo: string): Tarea, completar(id: number): Tarea y listar(): Tarea[]. Mantén la comprobación de tarea inexistente.
  5. Presentador: recibe Tarea[] y retorna void. Mantén la salida de consola y la opción de lista vacía.
  6. Entrada: conserva el ensamblaje en index.ts; compila y ejecuta la demostración.

El contrato puede vivir en su propio archivo, por ejemplo Repositorio.ts. Usa import type cuando una importación solo se necesite como tipo.

import type { Tarea } from "./Tarea.js";

export interface Repositorio {
  generarId(): number;
  guardar(tarea: Tarea): void;
  buscarPorId(id: number): Tarea | undefined;
  listar(): Tarea[];
}

Las pruebas son JavaScript y llaman al código en ejecución. Tras renombrar src, cambia sus imports de ../src/... a ../dist/..., compila y ejecuta npm.cmd test. La prueba con null sigue comprobando la validación en ejecución, aunque una llamada equivalente desde TS sea inválida.

12. Ejercicios y comprobación final

Ejercicios

  1. Añade una operación pendientes(): Tarea[] en el servicio. Verifica una lista vacía y otra con tareas de ambos estados.
  2. Modela un resultado discriminado { ok: true; tarea: Tarea } | { ok: false; error: string } para una nueva operación de consulta; procesa ambos casos sin aserciones.
  3. Define un repositorio alternativo en memoria que implemente la interfaz y úsalo con el mismo servicio. ¿Qué código del servicio tuvo que cambiar?

Criterios de aceptación de la migración

  • La compilación con strict finaliza sin errores ni any añadido para ocultarlos.
  • El programa compilado produce los mismos estados y títulos que el original.
  • Las pruebas existentes apuntan al código compilado y pasan después de compilar.
  • Los datos inválidos y los identificadores inexistentes siguen produciendo errores explícitos.
  • El servicio depende de la interfaz; el repositorio resuelve búsquedas ausentes de forma segura.
  • Cada clase mantiene su responsabilidad y los datos siguen siendo exclusivamente en memoria.
